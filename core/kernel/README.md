# `core/kernel` — process primitives

## 1. What it is

The lowest layer of Core: config loading, the database (pg pools + Kysely
instances + the unit-of-work + the Prisma-migration runner), structured logging
+ request context, id generation, the clock, the error types, the ambient tenant
context, the DI **tokens**, and `KernelModule` (a `@Global` module that exposes
these singletons to the Nest container).

## 2. Why it exists

Every module needs config, a clock, transactions, ids, logging, and error types.
They must be *one* implementation, available *everywhere*, and *swappable in
tests*. Importing them ad hoc would make that impossible.

## 3. What problem it solves

- One place that reads and validates environment config (a bad env fails fast at
  boot, not deep in a request).
- One unit-of-work so "the use case owns its transaction" is enforceable.
- Deterministic tests: `CLOCK` and `UNIT_OF_WORK` are overridden per test.
- A tenant context that RLS and repositories can read without threading
  `organizationId` through every function.

## 4. Responsibilities

- `config.ts` — parse + validate `AURIC_*` env into `AuricConfig`.
- `db/` — `pool.ts` (pg pools: app + system role), `db.ts` (Kysely + `unitOfWork`
  + pool close), `schema.ts` (generated by `prisma-kysely`), `migrate.ts`
  (`migrateToLatest`, `migrationStatus` — shells `prisma migrate deploy`).
- `logging/` — `pino` logger, `moduleLogger`, `withContext` / `runAsSystem`
  correlation-id propagation.
- `clock.ts` — `systemClock` (`Clock` interface).
- `id.ts` — prefixed, sortable ids (`newId("usr")` → `usr_…`).
- `errors.ts` — `AppError` and constructors: `ValidationError`, `Unauthenticated`,
  `Forbidden`, `NotFound`, `Conflict`, `Internal`.
- `tenant.ts` — `tenantContext` (`ITenantContext`), `requireOrganizationId`,
  `currentOrganizationId`, `isSystemContext`, `runAsSystem`.
- `tokens.ts` — every DI `Symbol` (see below).
- `kernel.module.ts` — binds `CONFIG`, `CLOCK`, `UNIT_OF_WORK`, `ERROR_TRACKER`,
  `TENANT_CONTEXT`; closes DB pools on shutdown.

## 5. What it owns

The `AuricConfig` shape, the pg pools + Kysely instances, the generated
`schema.ts` types, the id scheme, the `AppError` taxonomy, and the token
`Symbol`s. It does **not** own any table.

## 6. What it explicitly does NOT own

- Business or platform *data* — no repositories for User/Org/etc. (those are in
  their modules).
- HTTP concerns (guards, filters, pipes → `core/http`).
- The event bus / outbox (→ `core/events`), though the outbox uses the
  unit-of-work.
- Migration *authoring* — that is `prisma migrate dev` against
  `prisma/schema/`; kernel only *applies* migrations.

## 7. Public surface

- `KernelModule` (import once, near the top of the composition root).
- Tokens (`core/kernel/tokens.ts`, re-exported from `core/index.ts`):
  `CONFIG`, `CLOCK`, `UNIT_OF_WORK`, `AUDIT_LOGGER`, `EVENT_BUS`,
  `USER_PROVIDER`, `ORGANIZATION_PROVIDER`, `PERMISSION_PROVIDER`,
  `NOTIFICATION_PROVIDER`, `FILE_STORAGE`, `TENANT_CONTEXT`, `EMAIL_CHANNEL`,
  `PASSWORD_HASHER`, `ERROR_TRACKER`, `JWT_SERVICE`, `STORAGE_ADAPTER`,
  `REQUIRE_EMAIL_VERIFICATION`, `WORKER_AUTOSTART`.
- `migrateToLatest`, `migrationStatus`.
- Tenancy helpers: `tenantContext`, `requireOrganizationId`, …
- `AppError` + constructors, `moduleLogger`, `newId`, `getDb`, `unitOfWork`.

## 8. How to use

```ts
// A use case:
constructor(
  @Inject(UNIT_OF_WORK) private readonly uow: UnitOfWork,
  @Inject(CLOCK)        private readonly clock: Clock,
) {}

async doThing(input: X) {
  return this.uow.transaction(async () => {
    // reads + writes here run in ONE transaction, RLS-scoped to the active tenant
    if (bad) throw ValidationError("thing.invalid", "…");
    // …
  });
}
```

Never `new Pool()` or `import { db }` outside kernel — inject `UNIT_OF_WORK` /
use `getDb()` from kernel.

## 9. Dependencies & direction

Depends only on `core/contracts` and third-party libs (pg, kysely, pino, zod).
**Every other Core module and all of `app/` depend on kernel.** Kernel depends on
nothing in Core above it.

## 10. Invariants

1. Config is read once at startup and validated; missing/invalid env is a boot
   failure.
2. There is exactly one `unitOfWork`. A use case opens exactly one transaction.
3. `CLOCK` is the only source of "now" — no `new Date()` / `Date.now()` in domain
   or application code.
4. Ids come from `newId(prefix)` — no raw UUIDs in domain code.
5. Errors are `AppError` subclasses; the HTTP filter maps them to status codes.
   Throwing a bare `Error` is a bug.
6. The tenant is read from `tenantContext`, never passed as an argument through
   business code.

## 11. Example — deterministic test

```ts
const clock = fixedClock("2026-01-01T00:00:00Z");
const moduleRef = await Test.createTestingModule({ imports: [AppModule] })
  .overrideProvider(CLOCK).useValue(clock)
  .compile();
```

## 12. Testing expectations

`core/kernel/tests/` covers: config validation rejects bad env; ids are sortable
and prefixed; `AppError` maps correctly; `withContext` propagates correlation
ids; the unit-of-work rolls back on throw. Consumers override `CLOCK` /
`UNIT_OF_WORK` rather than mocking pg.

## 13. When NOT to extend it

- To add a repository or any table-specific code — that belongs in a module.
- To add framework glue (interceptors, guards) — that is `core/http`.
- To add a second config source or a runtime config-reload mechanism without a
  real requirement.
